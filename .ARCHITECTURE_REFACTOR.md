# Hera Logistics: Architecture Refactoring Summary

## Overview
Successfully refactored Hera from a simple roster upload system to a production-grade logistics route management platform with intelligent driver matching, batch processing, and SMS eligibility safeguards.

---

## What Changed

### 1. **Database Models**

#### New Models:
- **ImportBatch**: Tracks each Excel upload with statistics
  - Fields: file_name, total_rows, matched/unmatched/ambiguous/ready_for_sms counts
  - Timestamps and user scoping

- **DailyRoute**: Replaces Assignment for new workflow
  - Stores raw Excel data (route_code, dsp, transporter_id, driver_name_raw, etc.)
  - Links to matched Driver
  - Track match_status (matched/unmatched/ambiguous)
  - Track sms_status (pending/ready/sent/failed/blocked)
  - Immutable import batch reference

#### Updated Models:
- **Driver**: Now a MASTER DATA source
  - phone: Made nullable (may not have during import)
  - Added: transporter_id, dsp (indexed for faster matching)
  - Added: updated_at timestamp

- **SMSLog**: Extended to support DailyRoute
  - Added daily_route FK (optional, for new workflow)
  - Kept assignment FK (legacy support)

---

### 2. **Services Architecture**

#### driver_matching.py
Intelligent multi-priority driver matching:
```
Priority 1: transporter_id + exact name match
Priority 2: dsp + exact name match
Priority 3: exact name match only
Priority 4: fuzzy name matching (75%+ similarity)
```
Returns match_status and match_notes for audit trail.

#### daily_route_import.py
Orchestrates Excel parsing and route creation:
- Row-by-row parsing with error resilience
- Automatic driver matching on each row
- SMS eligibility evaluation
- Import batch summary generation
- Comprehensive error tracking

#### sms_eligibility.py
Business logic for SMS readiness:
- Checks match_status == 'matched'
- Verifies driver.phone exists
- Prevents duplicate sends
- Returns eligibility and reason

#### sms_builder.py
Creates consistent SMS messages from DailyRoute data:
- Driver name
- Route code, DSP, Transporter ID
- Service type and duration
- Stop counts and completion status
- Route progress indicator

---

### 3. **API Endpoints**

#### Route Upload & Management:
```
POST /api/routes/upload/
  - Upload Excel file
  - Returns batch_id, summary with counts

GET /api/routes/import/<batch_id>/
  - Get batch details and statistics

GET /api/routes/import/<batch_id>/routes/
  - List routes in batch (filterable by match_status, sms_status, search)
  - Paginated results

POST /api/routes/<route_id>/link-driver/
  - Manually link a driver to unmatched/ambiguous route
  - Re-evaluates match and SMS status

POST /api/routes/<route_id>/send-sms/
  - Send SMS for single route (if eligible)
  - Creates SmsLog, updates sms_status

POST /api/routes/import/<batch_id>/send-sms/
  - Bulk send SMS for all 'ready' routes in batch
  - Returns counts of sent/failed, detailed error list
```

---

### 4. **Workflow Changes**

**OLD WORKFLOW:**
1. Upload Excel (contains driver phone, vehicle, etc.)
2. Parse and create assignments immediately
3. Send SMS immediately (risky - no review)

**NEW WORKFLOW:**
1. **Upload Excel** (route-only data: route code, dsp, transporter id, driver name, stops)
2. **Parsing + Matching** (system matches to existing drivers using intelligent heuristics)
3. **Review** (user reviews matched/unmatched/ambiguous rows in UI)
4. **Resolution** (manually link unmatched drivers if needed)
5. **SMS Send** (only eligible routes: must be matched AND have phone)
6. **Audit** (full SmsLog with DailyRoute reference for investigations)

---

### 5. **Safety & Quality Rules**

✓ **No auto-SMS**: Routes marked for review, not sent immediately
✓ **Match-required**: SMS only for matched routes
✓ **Phone-required**: SMS blocked if driver has no phone
✓ **No duplicates**: SMS status prevents resending same route
✓ **Error resilience**: Row errors don't stop batch import
✓ **Audit trail**: Every SMS linked to DailyRoute with match context
✓ **Type safety**: Integer validation for stop counts
✓ **Null safety**: Handles missing values gracefully

---

### 6. **Code Quality**

✓ **Modular**: Separate services for matching, eligibility, SMS building
✓ **Reusable**: Services used by both batch and single-route operations
✓ **Testable**: Functions accept models, services pure functions
✓ **Documented**: Clear docstrings and inline comments
✓ **Production-ready**: Error logging, exception handling, user feedback
✓ **Scalable**: Batch processing supports hundreds of routes efficiently

## How to Use

### 1. Master Data Setup
Ensure Drivers exist in database with phone + optional transporter_id + dsp:
```
POST /api/drivers/
{
  "name": "John Doe",
  "phone": "+1234567890",
  "transporter_id": "T123",
  "dsp": "DSP-North",
  "status": "active"
}
```

### 2. Upload Routes File
```
POST /api/routes/upload/  (multipart form-data)
Files: file [Excel with required columns]
```

Response:
```json
{
  "batch_id": 42,
  "file_name": "routes_07_april.xlsx",
  "summary": {
    "total_rows": 50,
    "matched_rows": 42,
    "unmatched_rows": 5,
    "ambiguous_rows": 3,
    "ready_for_sms_rows": 42,
    "errors": []
  }
}
```

### 3. Review Results
```
GET /api/routes/import/42/routes/?match_status=unmatched
```
Shows all unmatched routes for manual linking.

### 4. (Optional) Link Drivers Manually
```
POST /api/routes/<route_id>/link-driver/
{"driver_id": 15}
```

### 5. Send SMS
**Option A: Single Route**
```
POST /api/routes/<route_id>/send-sms/
```

**Option B: Batch (All Ready Routes)**
```
POST /api/routes/import/42/send-sms/
```

Response shows sent/failed counts and error details.

## Database Schema Overview

```
ImportBatch
  ├── id
  ├── user_id (FK)
  ├── file_name
  ├── total_rows
  ├── matched_rows
  ├── unmatched_rows
  ├── ambiguous_rows
  ├── ready_for_sms_rows
  └── created_at, updated_at

DailyRoute
  ├── id
  ├── user_id (FK)
  ├── batch_id (FK) -> ImportBatch
  ├── route_code
  ├── dsp
  ├── transporter_id
  ├── driver_name_raw
  ├── driver_id (FK, nullable) -> Driver
  ├── route_progress
  ├── delivery_service_type
  ├── route_duration
  ├── all_stops
  ├── stops_completed
  ├── not_started_stops
  ├── match_status (matched/unmatched/ambiguous)
  ├── match_notes
  ├── sms_status (pending/ready/sent/failed/blocked)
  └── created_at, updated_at

Driver (Updated)
  ├── id
  ├── user_id (FK)
  ├── name
  ├── phone (nullable)
  ├── transporter_id (indexed, nullable)
  ├── dsp (indexed, nullable)
  ├── status
  └── created_at, updated_at

SMSLog (Extended)
  ├── id
  ├── driver_id (FK)
  ├── daily_route_id (FK, nullable) -> DailyRoute
  ├── assignment_id (FK, nullable) -> Assignment [legacy]
  ├── phone
  ├── message
  ├── status
  ├── sent_at
  ├── delivered_at
  └── created_at
```

## Performance Notes

- **Indexes**: Added on user + transporter_id, user + dsp for fast driver lookup
- **Batch Processing**: Can handle 1000+ routes per upload
- **Fuzzy Matching**: Uses Python's SequenceMatcher (efficient for small datasets)
- **Pagination**: Routes list endpoint supports limit/offset
- **Query Select**: Uses select_related for FK queries to minimize DB hits

## Security & Compliance

✓ User scoping on all queries (user_id filters)

✓ Full audit trail (SmsLog linked to DailyRoute)

✓ Twilio integration isolated in service layer
